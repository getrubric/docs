title: "GET /v1/audit"
description: "List audit events for the org with filters and cursor pagination."

---

Powers the dashboard's [Audit log](/dashboard/audit-log) page. Use this from CI for export, alerting, or compliance reports.

## List events

```http
GET /v1/audit?limit=50&decision=deny&search=delete
Authorization: Bearer <Clerk session JWT>
```

### Query params

| Param | Type | Default | Notes |
| --- | --- | --- | --- |
| `limit` | int | `50` | Max page size. Capped at `200`. |
| `decision` | `"allow" \| "deny" \| "all"` | `"all"` | Filter by decision. |
| `search` | string | — | Case-insensitive ILIKE across `toolName`, `sessionId`, `agentId`. |
| `agentId` | string | — | Exact-match filter. |
| `cursor` | string | — | `${ts}\|${id}` from the previous response's `nextCursor`. |

### Response 200

```json
{
  "entries": [
    {
      "id": "9c2e5d4b-...",
      "ts": "2026-05-10T15:09:29.123Z",
      "agentId": "payments-bot",
      "sessionId": "sess-42",
      "toolName": "delete_file",
      "decision": "deny",
      "policyId": "...",
      "policyVersion": 4,
      "latencyMs": 0.18,
      "denyCode": "no-delete",
      "denyReason": "Deny delete_file calls",
      "hasTrace": true
    }
  ],
  "nextCursor": "2026-05-10T15:09:00.000Z|abc-123-..."
}
```

`nextCursor` is `null` when there are no more rows.

### Pagination

Cursor-based on `(ts desc, id desc)` for stability under concurrent ingest. To page:

```bash
# First page
curl "$RUBRIC_API/v1/audit?limit=50&decision=deny" \
  -H "Authorization: Bearer $CLERK_JWT"

# Next page using the returned nextCursor
curl "$RUBRIC_API/v1/audit?limit=50&decision=deny&cursor=2026-05-10T15:09:00.000Z%7Cabc-123" \
  -H "Authorization: Bearer $CLERK_JWT"
```

## Fetch a trace

```http
GET /v1/audit/:id/trace
Authorization: Bearer <Clerk session JWT>
```

Returns the trace blob attached to the audit event with id `:id`.

### Response 200

```json
{
  "traceId": "9c2e5d4b-...",
  "messages": [...],
  "highlightPosition": 12
}
```

| Field | Notes |
| --- | --- |
| `messages` | The full ordered transcript. |
| `highlightPosition` | Which message the audit event is for. The dashboard scrolls and highlights this row. |

### Errors

| Status | Type | When |
| --- | --- | --- |
| `404` | `not_found` | Audit event exists but has no trace attached, or the trace blob is missing. |

The SDK shows a friendly empty state on 404 explaining how to attach traces by passing a `TraceContext` to `evaluate()`.

## Auth

Both `/v1/audit` and `/v1/audit/:id/trace` are clerk-authenticated. They're not callable from the SDK direction — agents cannot read each other's audit events.
