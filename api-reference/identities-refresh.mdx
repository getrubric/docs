---
title: "POST /v1/identities/refresh"
description: "Get a fresh JWT-SVID before the current one expires."
icon: "rotate"
---

The SDK calls this around the 50-minute mark of a JWT's 60-minute lifetime to keep your agent authenticated indefinitely (until you revoke or rotate).

## Request

```http
POST /v1/identities/refresh
Authorization: Bearer <current JWT-SVID>
```

No body.

## Response 200

```json
{
  "token": "eyJhbGciOiJFZERTQSI...",
  "expiresAt": "2026-05-10T17:09:29.123Z",
  "agentId": "payments-bot",
  "identityId": "9c2e5d4b-..."
}
```

The same shape as `/enroll` and `/exchange`. New `token`, new `expiresAt`, same `agentId` and `identityId`.

## Errors

| Status | Type | When |
| --- | --- | --- |
| `401` | `invalid_identity` | Current JWT is invalid (revoked, expired, malformed). |
| `403` | `forbidden` | The identity has been revoked since this JWT was issued. |

## Refresh strategy

The SDK refreshes proactively, well before the JWT expires:

- Schedule a refresh at `iat + 50 minutes` (10 minutes before expiry).
- On failure, retry with exponential backoff (1s, 2s, 4s, …, capped at 60s).
- If retries exhaust within the remaining window, the SDK surfaces a `GovernanceProblemError` to the next `evaluate()` caller. (Rare — usually means the network is down for >10 minutes.)

This means transient API outages do not interrupt your agent. The SDK keeps using the still-valid JWT and refreshes successfully when the API recovers.

## cURL

```bash
curl -X POST $RUBRIC_API/v1/identities/refresh \
  -H "Authorization: Bearer $CURRENT_JWT"
```
