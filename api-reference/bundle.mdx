---
title: "GET /v1/bundle"
description: "Pull the org's current policy bundle."
icon: "cube"
---

The SDK polls this every 30 seconds (configurable) to keep the in-process evaluator current with what operators have published.

## Request

```http
GET /v1/bundle
Authorization: Bearer <JWT-SVID>
If-None-Match: "<etag from last response>"
```

`If-None-Match` is optional but strongly recommended — the SDK uses it to avoid re-downloading an unchanged bundle.

## Response 200

```json
{
  "orgId": "...",
  "bundleVersion": 4,
  "publishedAt": "2026-05-10T15:00:00.000Z",
  "policies": [
    {
      "policyId": "...",
      "policyVersion": 2,
      "document": {
        "apiVersion": "agent-governance.io/v1",
        "kind": "Policy",
        "metadata": { ... },
        "spec": { ... }
      }
    }
  ]
}
```

| Field | Notes |
| --- | --- |
| `bundleVersion` | Monotonic per-org. Increments on every publish. |
| `publishedAt` | When the most recent policy was published. |
| `policies` | Every active policy's current version, fully expanded. |

## Response 304

If `If-None-Match` matches the current bundle's `ETag`, you get an empty `304 Not Modified`. The SDK keeps using its cached bundle.

## Cache headers

```
ETag: "abc123..."
Cache-Control: private, max-age=10
```

`max-age` is intentionally short — operators expect new policies to take effect within tens of seconds, not minutes. The SDK's 30-second poll dominates regardless.

## Errors

| Status | Type | When |
| --- | --- | --- |
| `401` | `invalid_identity` | JWT missing, malformed, revoked, or expired. |

## cURL

```bash
curl $RUBRIC_API/v1/bundle \
  -H "Authorization: Bearer $JWT"
```

## Empty bundle

Newly-created orgs with no policies return an empty bundle:

```json
{ "orgId": "...", "bundleVersion": 0, "publishedAt": null, "policies": [] }
```

The SDK's evaluator with an empty bundle returns `decision="allow"` for every call (the implicit default-allow). Add a policy and within ~30 seconds the SDK starts enforcing it.
