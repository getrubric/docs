The Rubric REST API is the source of truth for everything the dashboard and the SDK do. It's stable, versioned (`/v1`), and documented here.

## Base URLs

| Environment | URL |
| --- | --- |
| Local | `http://localhost:3001` |
| Production (deployed control plane) | Your URL |

## Endpoints by direction

The API has three groups of routes, distinguished by **who calls them** and **what authenticates the call**.

### SDK direction (your agent → control plane)

These are called by the Rubric SDK in your agent process. They authenticate with a **JWT-SVID** issued at enrollment.

| Method | Path | Page |
| --- | --- | --- |
| `POST` | `/v1/identities/enroll` | [Enroll via token](/api-reference/identities-enroll) |
| `POST` | `/v1/identities/refresh` | [Refresh a JWT](/api-reference/identities-refresh) |
| `GET`  | `/v1/bundle` | [Pull the policy bundle](/api-reference/bundle) |
| `POST` | `/v1/events` | [Ship audit events](/api-reference/events) |
| `POST` | `/v1/traces` | [Upload a trace](/api-reference/traces) |

`/v1/bundle` is **per-agent** — the response is the intersection of the org's active policies with the requesting agent's scope. An agent with no scoped policies receives an empty (but cryptographically signed) bundle.

### Dashboard direction (operator → control plane)

These are called by the dashboard (and you can call them directly from CI). They authenticate with a **Clerk session token**.

| Method | Path | Notes |
| --- | --- | --- |
| `GET / POST / PATCH / DELETE` | `/v1/agents`, `/v1/agents/:id`, `/v1/agents/:id/activity` | Agent CRUD + per-agent activity. |
| `GET / POST / PATCH / DELETE` | `/v1/policies`, `/v1/policies/:id`, `/v1/policies/:id/activity` | Policy authoring + per-policy activity. |
| `PUT` | `/v1/policies/:id/scope` | Replace the set of agents a policy enforces against. |
| `GET` | `/v1/policy-templates` | Starter templates. |
| `GET` | `/v1/insights` | Aggregate timeseries / top-tools / top-deny-reasons. |
| `GET / POST / DELETE` | `/v1/enrollment-tokens`, `/v1/enrollment-tokens/:id`, `/v1/enrollment-tokens/:id/renew` | Manage enrollment tokens. |
| `GET / PATCH` | `/v1/incidents`, `/v1/incidents/:id`, `/v1/incidents/:id/timeline` | Incident triage. |
| `GET` | `/v1/audit`, `/v1/audit/:id/trace` | [Audit log + trace fetch](/api-reference/audit). |

### Public

| Method | Path | Auth | Notes |
| --- | --- | --- | --- |
| `GET` | `/health` | None | Liveness probe. Returns `{"ok":true}`. |

## Versioning

Everything is mounted under `/v1`. Breaking changes will land under `/v2` with a deprecation period; the current `v1` is stable and we don't plan a `v2` in the near term.

## Content types

- **Requests** — `application/json`.
- **Successful responses** — `application/json`.
- **Errors** — `application/problem+json` (RFC 9457).
