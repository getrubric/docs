Rubric is split into two pieces: the **SDK** that runs in your agent process, and the **control plane** we host for you. They talk over HTTPS — the SDK pulls policy bundles and ships audit events; the control plane stores policies, ingests audit events, and serves the dashboard.

```
┌────────────────────────┐   bundle pull (every 30s)    ┌──────────────────┐
│  Your agent process    │ ──────────────────────────► │                  │
│  ┌──────────────────┐  │                              │  Rubric control  │
│  │ Rubric SDK       │  │   audit events (batched)     │  plane (hosted)  │
│  │  · evaluator     │  │ ──────────────────────────► │                  │
│  │  · bundle cache  │  │                              │   Operators →    │
│  │  · audit sink    │  │   trace upload (per call)    │   Dashboard      │
│  │  · trace upload  │  │ ──────────────────────────► │                  │
│  └──────────────────┘  │                              │                  │
│         ▲              │   JWT exchange / refresh     │                  │
│         │ in-process   │ ◄──────────────────────────  │                  │
│  ┌──────┴──────┐       │                              └──────────────────┘
│  │  Tool call  │       │
│  └─────────────┘       │
└────────────────────────┘
```

## SDK — in your process

The SDK runs in-process, in the same Python interpreter as your agent. Three responsibilities:

- **Evaluator.** A pure-Python (or Rust, with `[runtime]`) interpreter for your policy bundle. `evaluate()` is sub-millisecond — no network round-trip on the hot path.
- **Bundle cache.** A background poller refreshes the bundle every 30 seconds. If the control plane is unreachable, the SDK keeps using the last-known-good bundle (fail-open by default; configurable).
- **Audit sink.** Every `evaluate()` enqueues an audit event. A background flush thread batches them and ships to the control plane (default: every second or 100 events, whichever first).

The SDK never blocks your tool dispatch on a network call. Outages of the control plane do not stop your agent.

## Control plane — hosted by us

The control plane is the service your SDK calls and your operators use. What it does for you:

- Issues each agent a short-lived (60-minute) signed identity, auto-refreshed by the SDK
- Stores your policies (versioned, with diff and dry-run) and serves them as a per-agent bundle
- Ingests audit events and traces, opens incidents on deny spikes and high-severity DLP hits
- Hosts the dashboard your operators sign into

You don't run any of this. You point the SDK at the API URL we give you, mint an enrollment token from the dashboard, and ship.

## Trust model

Rubric is opinionated about *who can do what*:

| Actor | Credential | Can do | Cannot do |
| --- | --- | --- | --- |
| **Operator** | Dashboard sign-in | Manage policies, identities, enrollment tokens, read the audit log | Forge an agent's identity |
| **Enrollment token** | `enr_…` (long-lived) | Bootstrap a new agent identity | Anything else (no audit ingest, no bundle reads) |
| **Agent (SDK)** | Short-lived signed identity (60 min) | Pull its bundle, ship audit events for *its own* agent id, upload traces | Impersonate a different agent — the control plane rejects any event whose agent id doesn't match the identity it was sent with |

There is no other way to ship attribution. Audit events and trace uploads are cryptographically bound to the SDK's identity.

## Failure modes

| Failure | What happens |
| --- | --- |
| Control plane unreachable | SDK uses last-known-good bundle. Audit events queue in memory; flushed on recovery. |
| Bundle stale | `gov.current_bundle.bundleVersion` reflects the last successful pull. Optionally enforce a max-age in your harness. |
| Identity expires during outage | SDK auto-refreshes ahead of expiry. Transient refresh failures are retried; the still-valid identity keeps working until it expires. |
| Process restart with same `agentName` | Enrollment is idempotent — same `(org, agentName)` resolves to the same identity. Fresh signed token, same agent id. |
| Process restart with revoked identity | Enrollment is rejected. Operator must un-revoke or use a different name. |
