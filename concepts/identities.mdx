Every governed agent has its own cryptographic identity — a short-lived JWT-SVID issued by the control plane, bound to a stable `agentId`. The SDK obtains and refreshes it automatically. You don't write any of this code yourself.

## What's a JWT-SVID?

A [SPIFFE-style](https://spiffe.io/) signed JWT with a few claims that matter:

```json
{
  "iss": "https://api.rubric.dev/v1",
  "aud": "rubric",
  "sub": "payments-bot",
  "org": "6acf0ca4-4453-4026-bc22-d0f316e1beb8",
  "identity_id": "...",
  "iat": 1715361600,
  "exp": 1715365200
}
```

- **`sub`** — the agent's stable id. Audit ingest, trace upload, and bundle reads all assert this claim against the body.
- **`exp`** — 60 minutes from issuance. The SDK auto-refreshes around the 50-minute mark.
- **EdDSA-signed.** Signing key is per-org and stays inside the control plane. The public key is served at `/v1/identities/jwks` for verification.

## Two ways to bootstrap

You pick one based on whether you're shipping one agent or a fleet.

### Enrollment tokens (recommended for fleets)

A long-lived, org-scoped, **register-only** credential. The SDK calls `POST /v1/identities/enroll` with the token and an `agentName`, and gets back a freshly-minted JWT.

```python
from agent_governance import Governance

# AG_ENROLLMENT_TOKEN and AG_AGENT_NAME from env
with Governance.bootstrap(agent_name="payments-bot") as gov:
    ...
```

Properties:

- **Idempotent on `agentName`** — the same `(orgId, agentName)` always resolves to the same `agent_identities` row. Restarts and redeploys don't pile up identities; only the JWT rotates.
- **Register-only** — leaked enrollment token cannot ship audit events or read bundles. Worst case: an attacker creates new agent rows in your org. Bounded, auditable, revocable per-token.
- **Rate-limited** — each token has a `maxEnrollmentsPerHour` cap (default 60). Brute-force protection.
- **Expires** — 90 days by default; renewable from the dashboard with a successor token.

This is the right path for any runtime that ships > 1 agent. CI environments, multi-tenant agents, anything spawned dynamically.

### Provisioning secrets (single agent)

A one-time secret operator-issued in the dashboard. Consumed on first call, becomes invalid afterward.

```python
# AG_PROVISIONING_SECRET from env
with Governance.bootstrap() as gov:
    ...
```

Use this when:
- You only have one agent.
- You want explicit per-agent control over which agents exist.
- You're doing a security demo and want to show the issuance flow.

## Lifecycle

<Steps>
  <Step title="Bootstrap">
    SDK reads `AG_ENROLLMENT_TOKEN` (or secret) and calls `/v1/identities/enroll` (or `/exchange`). Server returns a JWT and the agent's stable id.
  </Step>
  <Step title="Auto-refresh">
    The SDK schedules a refresh at ~50 min into the token's lifetime, calling `/v1/identities/refresh` with the current JWT to get a fresh one. The agent never sees a 401.
  </Step>
  <Step title="Revocation">
    Operator clicks **Revoke** on an identity in the dashboard. The current JWT keeps working until expiry (max 60 min). New refresh attempts return 401. New enrollment for the same `agentName` returns 403 — operator must un-revoke or rename.
  </Step>
  <Step title="Process exit">
    `Governance.shutdown()` (or the `with` block exiting) stops the refresh thread. Next process boot re-enrolls and resumes with a fresh JWT against the same identity row.
  </Step>
</Steps>

## Naming

`agentName` is what you pass to `bootstrap(agent_name=…)`. The control plane normalizes this into the agent's stable `agentId` (lowercase, dash-separated, max 128 chars).

Choose names that:

- **Identify the role**, not the host. `payments-bot`, `customer-support-router` — not `agent-prod-us-east-1c`.
- **Survive redeployment.** The whole point of the idempotent enrollment is that `payments-bot` v2 inherits v1's identity.
- **Differ across environments.** Use a suffix or a separate org per environment: `payments-bot-stage` vs `payments-bot-prod`.

## Provenance

Every identity record in the dashboard carries its source:

- `enrolled · <tokenName>` — created via an enrollment token. Click through to the token that minted it.
- `manual` — issued individually via a provisioning secret.

This is your trail when you need to answer *"how did this agent get an identity?"* during an audit.
